# ファイルの管理方針

本プロジェクトでは、コードや技術仕様の再現性を担保しつつ、実機検証時の大容量データや個体情報がリポジトリに混入することを防ぐため、**「Git管理するもの」** と **「ローカルに留めるもの」** を明確に分離しています。

---

## 管理方針の原則

1. **コードと共通仕様はGit管理**: ソースコード、テストコード、共通の技術仕様書、起動用スクリプトはすべてGitで管理します。
2. **個体差・測定データ・日誌はローカル保持**: 「特定の個体シリアル」「取得日時ごとの生パケットデータ」「個別の試行錯誤の日誌」はGitにコミットせずローカルに保持します。

---

## 1. Gitで管理するもの

| ディレクトリ / ファイル | 役割・内容 |
|---|---|
| `src/nreal_air/` | アプリケーション本体（HID通信、VQF姿勢推定、並進積分、SSE配信サーバー） |
| `web/` | フロントエンド実装（HTML、Vanilla CSS、Vanilla JS） |
| `Air Viewer.command` | macOS用ダブルクリック起動ランチャースクリプト |
| `pyproject.toml`, `uv.lock` | プロジェクト設定とPython実行環境の厳密な固定 |
| `tests/` | ユニットテストコードおよび実機非依存の最小限のテストフィクスチャ |
| `tools/` | 実機検証用スクリプト群（※ `tools/reference/` は比較用の旧実装リファレンス） |
| `README.md`, `docs/` | クイックスタート、アーキテクチャ仕様書、アルゴリズム解説、管理方針 |

---

## 2. ローカルのみに残すもの（Git対象外）

これらは `.gitignore` に登録されており、リポジトリには含まれません。

| ディレクトリ / ファイル | 内容 |
|---|---|
| `data/captures/` | `air-capture` で取得した実機の全IMUパケット（1,000Hz）およびHIDログ |
| `data/live/` | 接続セッションごとに取得・保存される個体情報および工場校正JSON |
| `data/reports/` | 検証スクリプト（`verify_live.py` 等）が出力する診断レポートJSON |
| `data/*.csv`, `data/*.log` | ビューア画面から手動エクスポートしたCSVファイルやサーバー実行ログ |
| `local/notes/YYYY-MM-DD/` | 個人の作業日誌、過去スナップショット、画面キャプチャ、調査メモ |
| `.venv/` | `uv` により構築されるローカル仮想環境 |

> **注意**: これらは新規クローン時には存在しません。必要な個体データや検証ログは必要に応じて各自でバックアップしてください。

---

## 3. テスト用フィクスチャの扱い

- **`tests/fixtures/imu_report.json`**:
  - 実機の通信パケットから切り出した**64バイトのIMUパケット1件のみ**を格納しています。
  - シリアル番号、HIDパス、ホスト時刻、固有の校正データは一切含まれていません。
  - CIや別環境でも、実機や外部データなしでパーサーの完全な単体テストが実行可能です。

---

## 4. フィルター比較ツール (`tools/compare_filters.py`)

過去のキャプチャデータを用いた新旧フィルターの比較検証を行うツールです。

- **実行に必要なローカルデータ**:
  - `data/captures/20261021-205855/imu.jsonl`
  - `data/captures/20261021-205855/factory_calibration.json`
- **出力先**: `data/reports/vqf-comparison.json`
- **位置づけ**:
  過去のアルゴリズム移行調査を再実行するためのオプショナルな検証ツールです。通常のユニットテストやアプリ起動には不要です。また、実測データには真値（グランドトゥルース）が含まれないため、本ツールは挙動の差異を分析するためのものであり、精度の優劣を自動判定するものではありません。
